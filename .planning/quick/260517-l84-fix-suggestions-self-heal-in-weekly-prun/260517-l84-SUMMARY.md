# Quick Task 260517-l84: Suggestions Self-Heal in Weekly Prune — Summary

**One-liner:** `prune_suggestions_playlist_to_mirror` now self-heals when the user deletes the Composer · Suggestions Plex playlist mid-week — mirroring the same NotFound-detection + lazy-materialize pattern shipped for the per-play refill path in commit 719c6b7.

## What Changed

### Production patch (`app/services/plex_playlist_service.py`)

Split the single broad try-block (lines 576–633 of the patched file) into two
sequential try-blocks inside `prune_suggestions_playlist_to_mirror`:

1. **First try — read current Plex playlist contents.** On any exception:
   - `PermissionError` re-raises unchanged.
   - Otherwise, compute `err_str` and check for NotFound four ways:
     - `isinstance(exc, plexapi.exceptions.NotFound)`
     - `"notfound" in err_str`
     - `"not found" in err_str`
     - `"404" in err_str`
   - **If NotFound:** lazy-import `_materialize_suggestions_plex_playlist` from
     `suggestions_service`, await it with positional args
     `(plex_url, plex_token, sorted(mirror_keys))`, and return a `PruneResult`
     describing a heal (no `removed`, no `still_present_after_remove`,
     `mirror_size == len(sorted_mirror)`, `final_plex_count == len(sorted_mirror)`).
     The empty-mirror branch returns `PruneResult(mirror_size=0, final_plex_count=0)`
     after a no-op materialize call so the heal contract stays single-entry.
   - **Otherwise** (timeout, permission, network failure, anything non-NotFound):
     preserve original behavior — `raise type(exc)(_sanitize(str(exc), plex_token)) from None`.

2. **Second try — removal branch (logic unchanged).** Same removeItems → post-verify →
   update ManagedPlaylist sequence as before, just dedented out from the broader
   try. Preserves the verbatim `PermissionError`-passthrough and
   sanitize-and-re-raise wrapper from the prior implementation.

The lazy import sits at line 599 inside the heal branch — verified by
`grep -n "from app.services.suggestions_service" app/services/plex_playlist_service.py`
which shows exactly one match, indented inside a function body. **Never** at
module top (would cycle: `suggestions_service` already imports
`update_playlist_items` from `plex_playlist_service` at module level).

### Regression tests (`tests/test_plex_playlist_service.py`)

Added two `@pytest.mark.asyncio` tests after `test_prune_is_no_op_when_plex_subset_of_mirror`:

1. **`test_prune_self_heals_when_plex_playlist_vanished`** — Seeds
   `ManagedPlaylist(kind='suggestions', plex_rating_key='999')` and 3 mirror rows
   (rating_keys `"101","102","103"`). Monkeypatches
   `FakePlexServer.fetchItem` so calls with key `"999"` raise
   `plexapi.exceptions.NotFound("(404) not_found; <html>...</html>")`,
   delegating all other keys to the original. Monkeypatches
   `suggestions_service._materialize_suggestions_plex_playlist` with
   `AsyncMock(return_value="9001")`. Asserts:
   - `prune_suggestions_playlist_to_mirror` does NOT raise.
   - `materialize_mock.await_count == 1`.
   - `materialize_mock.await_args.args == ("http://plex.local", "token-X", ["101", "102", "103"])` (positional, sorted).
   - `result.removed == []`, `result.still_present_after_remove == []`,
     `result.mirror_size == 3`, `result.final_plex_count == 3`.

2. **`test_prune_self_heals_empty_mirror_returns_zero_count`** — Same fake-Plex
   NotFound setup but seeds ZERO mirror rows. Uses `caplog` at INFO. Asserts:
   - Materialize was still called once with `[]` as third arg.
   - `result.mirror_size == 0`, `result.final_plex_count == 0`.
   - An INFO log line containing `"mirror is empty"` was emitted by
     `app.services.plex_playlist_service`.

Both tests use the existing `db_with_suggestions` + `fake_plex_module` fixtures
(no new fixtures added) and reuse `_seed_suggestions_managed_playlist` +
`_seed_track_and_mirror` helpers.

## Why (production trace)

NAS log 2026-05-17 15:04:26: user deleted the Composer · Suggestions playlist
out of Plexamp. The Sunday 03:00 UTC `_weekly_maintenance_tick` then ran prune
→ `fetchItem(plex_rating_key=999)` raised `plexapi.exceptions.NotFound` →
scheduler swallowed the wrapped exception → `discovery_call_weekly` wrote 3
fresh picks to `SuggestionsMirror` → nothing ever touched Plex again. The
`ManagedPlaylist.plex_rating_key` stayed pointed at the deleted playlist
forever and the user never saw their Suggestions playlist come back.

Commit 719c6b7 had already shipped the equivalent heal for
`suggestions_service.refill_mirror_sql` (the per-play refill path), but the
weekly prune path was untouched. After this fix, EITHER trigger (per-play
refill OR weekly prune) recovers the playlist transparently.

## Invariants Pinned (Future Refactors MUST Preserve)

1. **NotFound detection runs BEFORE `_sanitize`/`raise`.** The existing
   sanitize call wraps via `raise type(exc)(_sanitize(str(exc), plex_token)) from None`
   which **does** preserve `type(exc)` — but earlier wrapping inside the same try
   block historically lost the chained predicate context. Keep the loose
   four-way detection (class + 3 substrings) running first; only fall through
   to sanitize on non-NotFound.

2. **`_materialize_suggestions_plex_playlist` MUST be lazy-imported inside the
   function body.** Top-level reverse import would cycle —
   `suggestions_service` already imports `update_playlist_items` from
   `plex_playlist_service` at module top. Verified by
   `grep -n "from app.services.suggestions_service" app/services/plex_playlist_service.py`
   showing the import indented (never at column 0).

3. **Heal branch calls materialize positionally with
   `(plex_url, plex_token, sorted(mirror_keys))`.** Empty mirror still
   triggers the call (with `[]`) — materialize itself early-returns None per
   `suggestions_service.py:266`. Future refactors MUST NOT gate the
   materialize call behind a non-empty mirror check; that would split the
   heal contract into two entry points.

4. **No edits to `sync_scheduler.py` or `suggestions_service.py`.** The fix is
   surgically confined to `plex_playlist_service.py` + its tests. Verified
   via `git diff --stat app/services/sync_scheduler.py app/services/suggestions_service.py`
   showing zero changes in this commit.

5. **The second try block's `PermissionError` re-raise + generic
   sanitize+raise MUST stay verbatim.** That wraps the removal-failure path,
   which is unchanged behavior and still load-bearing for non-heal exception
   handling (timeouts, permission errors, network failures during removeItems).
