<objective>
Fix the silent failure where the weekly Sunday 03:00 UTC maintenance tick gives up
permanently when the user deletes the Composer · Suggestions Plex playlist out from
under Composer. Today: prune raises NotFound -> scheduler swallows it -> discovery
writes 3 picks to SuggestionsMirror -> nothing ever touches Plex again. The
plex_rating_key in ManagedPlaylist stays pointing at the deleted playlist forever
and the user never sees their Suggestions playlist come back.

Purpose: extend the same self-heal pattern already shipped in
suggestions_service.refill_mirror_sql (commit 719c6b7) to the second code path
that touches the Plex playlist: prune. After this fix, EITHER trigger (per-play
refill OR weekly prune) recovers the playlist transparently.

Output: ~25 added lines in plex_playlist_service.py and one new pytest in
test_plex_playlist_service.py. No other files modified.
</objective>
