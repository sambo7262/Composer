# Phase 6.2 Plan 02: WIZ-08 "Start Over" Wizard Reset Summary

**Added a user-triggered destructive wizard reset (POST /api/setup/start-over) that archives Composer · Plex playlists with a date-stamped `(archived YYYY-MM-DD)` suffix, wipes Vibe / TrackVibe / ManagedPlaylist / SlotInLog + SetupState id=1 (including `draft_proposals_json=""`) + Track.pending_slot_in flags in one atomic transaction, preserves ServiceConfig + MigrationLog + LLMUsage + EventLog, and returns 204 + HX-Redirect=/setup so HTMX bounces the browser into a fresh wizard.**

## Accomplishments

- **WIZ-08 (Start Over wizard reset):** new POST /api/setup/start-over endpoint mirrors `run_phase_61_migration` architecture (app/main.py) minus the MigrationLog gate (D-27 — WIZ-08 is repeatable, not one-shot). Single in-handler atomic transaction: read managed playlists + Plex creds (via asyncio.to_thread) → archive each with date-stamped suffix under asyncio.Semaphore(1) (D-25) with TIGHT except `{PlexApiException, httpx.HTTPError, PermissionError, TypeError}` (WARNING #9 / T-062-15) → DB wipe in FK-safe order + SetupState reset + pending_slot_in clear in ONE Session.commit() inside ONE asyncio.to_thread → return 204 + HX-Redirect=/setup.
- **archive_playlist extension:** added `suffix: str = "(archived)"` as the 5th positional-or-keyword parameter. Default preserves byte-identical Phase 6.1 migration behavior; WIZ-08 callers pass `f"(archived {date.today().isoformat()})"` per D-26 to avoid `(archived) (archived)` collisions on repeated resets.
- **Settings UI surface:** red Start Over button in the Vibes section, visible only when `Vibe.count() > 0` (D-24 — never offer destruction when there's nothing to destroy). Click opens an Alpine modal with the D-25 locked content (Archive your current Composer playlists, "(archived YYYY-MM-DD)" suffix hint, Clear all vibe assignments, Restart the setup wizard, credentials preserved, This cannot be undone). Confirm hx-posts to /api/setup/start-over with `hx-swap="none"` (HTMX honors the 204 HX-Redirect).
- **Threat mitigations test-enforced:**
  - T-062-11 (T3): `test_start_over_preserves_serviceconfig_rows` — ServiceConfig rows for plex/anthropic/lidarr survive reset.
  - T-062-12 (T4): `test_start_over_plex_archive_failure_does_not_block_db_wipe` — single playlist archive failure doesn't block DB wipe or subsequent archive calls.
  - T-062-13: `test_setup_state_draft_proposals_json_cleared_post_reset` — draft_proposals_json="" post-reset (private-browser leak fix).
  - T-062-14 (T5): `test_archive_playlist_custom_suffix` + `test_start_over_archives_plex_playlists_with_date_suffix` — date-stamped suffix prevents Plex collision.
  - T-062-15: `test_start_over_tight_except_pattern` — AST scan asserts the start_over handler catches EXACTLY `{PlexApiException, HTTPError, PermissionError, TypeError}`; bare `except Exception` is forbidden.
  - T-062-18: `test_start_over_does_not_run_phase_61_migration_gate` — MigrationLog row preserved.

## Decisions Made

All decisions tracked in the frontmatter's `key-decisions` section. Highlights:

- **archive_playlist suffix default unchanged.** The 5th parameter defaults to `"(archived)"` so the Phase 6.1 first-deploy migration's 4-arg call (`app/main.py:145-150`) keeps working byte-identically. T5 regression guard: `test_archive_playlist_default_suffix_unchanged` covers this.
- **Endpoint placement below /reset.** The new /start-over sits below the existing /reset handler in api_setup.py — keeps the lighter "go back to Step 1" path available for mid-wizard restarts (D-24).
- **Imports inside the handler body.** Mirrors `run_phase_61_migration`'s pattern — keeps the handler self-contained, matches project convention for migration-style work.
- **AST scan scope.** `test_start_over_tight_except_pattern` walks ONLY the `async def start_over` body, so the existing `except Exception` clauses in propose_init/refine/finalize (with noqa BLE001) don't trigger false positives.
- **Modal hx-swap=none.** The endpoint returns 204 + HX-Redirect=/setup; HTMX honors the redirect; no response body to swap. Mirrors `/api/setup/reset`'s shape (D-24).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Test fixture bug] MigrationLog row fixture had UNIQUE constraint collision**
- **Found during:** Task 2 RED phase verification.
- **Issue:** The TestClient's lifespan auto-runs `run_phase_61_migration`, which inserts `MigrationLog(phase_id='6.1')`. The original test then tried to INSERT another row with the same phase_id → `sqlalchemy.exc.IntegrityError: UNIQUE constraint failed: migrationlog.phase_id`.
- **Fix:** Changed the test to query for the existing row and UPDATE its `completed_at` to a sentinel value, or INSERT only if absent. Same semantics; passes both the migration-already-ran and fresh-DB cases.
- **Files modified:** tests/test_api_setup.py
- **Verification:** test_start_over_does_not_run_phase_61_migration_gate passes.
- **Committed in:** beac2e9 (Task 2 commit).

**2. [Rule 1 - Test bug] min-h-11 / no-hover-only window too narrow**
- **Found during:** Task 3 GREEN phase verification.
- **Issue:** `body.find("Start Over")` returned the FIRST occurrence in the rendered HTML, which lands inside the `<!-- ... Phase 6.2 Plan 02 (WIZ-08 / D-24): adds a destructive "Start Over" button ... -->` comment block in settings.html — NOT inside the actual button. The 500/200-char window around that match didn't reach the button's class attribute, so the min-h-11 assertion failed.
- **Fix:** Added a `_find_start_over_button_block` helper that (a) strips HTML comments via regex, then (b) regex-matches `<button[^>]*>...Start Over...</button>` and returns the button block itself. Both `test_start_over_button_min_h_11_tap_target` and `test_start_over_button_no_hover_only_states` now use this helper. Production HTML unchanged.
- **Files modified:** tests/test_setup_templates.py
- **Verification:** all 8 Task 3 tests pass.
- **Committed in:** 364f6e7 (Task 3 commit).
