<objective>
Replace `map_user_vibes_to_clusters` with `assign_tracks_to_user_vibes`, a
two-pass LLM-direct membership pipeline that fulfills VIBE-13 (LLM-direct
assignment with confidence grades) and VIBE-14 (peer-context boundary review).

K-means stays in the file as a centroid-summary generator only — its `.labels_`
are discarded after the Pass 1 prompt is built. Final `Vibe.centroid_*` is the
mean of LLM-assigned members, making `slot_track` (Phase 6 D-15) measure
distance against centroids that faithfully reflect the LLM's groupings.

The plan ships in ONE commit set with all paired changes:
1. `anthropic_client.py` gains `thinking: Literal["off", "adaptive"] = "off"`
   AND robust `response.content` text-block iteration. Both changes ship
   together — the moment thinking returns a ThinkingBlock at `content[0]`,
   `response.content[0].text` raises AttributeError. T1 mitigation.
2. `vibe_clusterer.py` gains the two-pass pipeline, the two new slim schemas
   (`LLMVibeAssignmentResponse`, `LLMVibeBoundaryResponse`), a vibe-definition
   preamble call, retry-once per batch, server-side index/name validation
   (Pitfall 10), and a centroid-recompute step.

   shim. The function returns a `VibeProposalSet` of the existing shape so the
   downstream consumers (`/refine`, `/finalize`, `/api/vibes/recluster/commit`)
   are untouched (D-22).
4. `vibe_proposal_card.html` gains a Pass-2 confidence chip (per-track) so the
   user sees which tracks went through boundary review.
5. `/debug/vibes` cost panel segments LLMUsage by the three new purposes.
