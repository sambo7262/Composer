# Plan 05 scope additions (from Plan 04 UAT)

## ADDITION-1 — Manual "Run weekly tick now" button on /debug/discovery

**Why:** Discovery candidates only populate via the Sunday 03:00 UTC cron.
Operator (user) has no way to force a tick for UAT or after fixing a bug —
forced to wait up to 7 days. Plan 05 ships /debug/discovery anyway; a manual
trigger button is a one-line UI add and a thin POST route.

**Acceptance:**

1. `/debug/discovery` page has a `[Run weekly tick now]` button.
2. Button POSTs to a new route (e.g. `POST /api/discovery/run-tick-now`) that
   invokes `_weekly_maintenance_tick()` exactly as APScheduler would, in a
   background task so the request returns immediately.
3. Button is disabled (or returns 409) while a tick is already running —
   `discovery_service.get_state().state == "running"` is the gate.
4. After clicking, the user sees a toast / status line "Tick running…"; the
   debug page polls every 5s and reflects state transitions
   (`running` → `idle` / `error`).
5. The route is gated by the same is-localhost / settings-page-visibility check
   the rest of /debug/* uses (no public exposure).
6. Test coverage:
   - POST returns 202 + spawns background task
   - POST returns 409 if `state == "running"`
   - Background task wraps `_weekly_maintenance_tick` in try/except so a
     failure surfaces in logs and `_status.last_error` without raising.

## ADDITION-2 — Plan 04 UAT also surfaced "no candidates after manual cron"

Operator ran a manual cron via shell and saw `source=discovery_weekly` in the
suggestions refill log but `/discover` still showed the pre-first-tick empty
state. Most likely they invoked `discovery_call_weekly()` from
`suggestions_discovery` (which only runs step 2 of `_weekly_maintenance_tick`)
rather than the full tick.

The Plan 05 manual-trigger button **must** invoke `_weekly_maintenance_tick()`
(all 4 steps including `artist_discovery_call_weekly` and the
`WeeklyCronState.last_tick_at` stamp) — not the individual sub-functions —
so a single button populates both /discover AND the cost-chip "post-first-tick"
state correctly.
