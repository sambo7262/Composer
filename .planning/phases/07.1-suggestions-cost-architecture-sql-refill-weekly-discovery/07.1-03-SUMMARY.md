## Accomplishments

- Phase 7.1's user-facing observability story closes: the cost meter card on `/settings` now reads "Anthropic spend this week" with a rolling 7-day aggregation, $0.50 weekly budget, and neutral cache-hit copy. Operators can see the new weekly cadence in production.
- The dollar-budget constant rename (`DAILY_COST_BUDGET_USD = 0.42` → `WEEKLY_DISCOVERY_BUDGET_USD = 0.50`) is complete; the old name is fully removed (not aliased) and a unit test pins both the value and the absence.
- The Phase 5 hard-enforcement breaker thresholds (`DAILY_QUOTA = 50`, `BURST_LIMIT = 5`, `BURST_WINDOW_SECONDS = 60`, `DEBOUNCE_SECONDS = 30`) are explicitly pinned by a dedicated unit test — belt-and-suspenders against a future regression that re-introduces a per-event LLM loop.
- Seven AST regression tests guarantee the Phase 7.1 architecture cannot be silently undone:
  - 3 in `tests/test_suggestions_discovery.py::TestSuggestionsDiscoveryMaxTokensGuard` — no `max_tokens=2000` literal; no `max_tokens < 8000` literal; every `_*_sync` call inside an `async def` must go through `asyncio.to_thread`.
  - 4 in `tests/test_suggestions_service.py::TestNoLegacyLlmRefillRefs` — no `refill_suggestions_queue` def/call/attr; no `refill_suggestions_for_vibe` def/call; no `SUGGESTIONS_RANK_MAX_TOKENS` assignment or reference; no `call_with_structured_output` invocation.
- Each AST guard was smoke-verified live: I patched the live source to introduce the forbidden pattern, ran pytest, confirmed the guard FAILS with a precise file:line message, then reverted. The reverts are clean (verified via `git status` + a follow-up post-revert test run that passes).

## AST Regression Tests Added

### `tests/test_suggestions_discovery.py::TestSuggestionsDiscoveryMaxTokensGuard` (Task 2)

| Test | What it forbids |
|------|-----------------|
| `test_no_hardcoded_max_tokens_2000_in_suggestions_discovery` | Any keyword argument `max_tokens=2000` (literal int) in any Call node — the 260514-e6w truncation pitfall |
| `test_no_max_tokens_below_floor_in_suggestions_discovery` | Any keyword argument `max_tokens=N` where N is an `int` literal and N < `DISCOVERY_MAX_TOKENS_FLOOR` (8000). Symbolic refs pass — they're the preferred pattern |
| `test_all_sql_helpers_called_via_to_thread` | Any direct call to a name ending in `_sync` inside any `async def` that isn't the first positional arg of `asyncio.to_thread(...)` — Phase 5 D-09 |

### Not a Deviation — Decisions Confirming Plan Intent

Instead, I committed the tests as `test(...)` and verified each guard's effectiveness with a smoke test (patch live source → confirm FAIL → revert). This matches the plan's stated `<done>` section which lists smoke tests as "Manual smoke test, not committed."
