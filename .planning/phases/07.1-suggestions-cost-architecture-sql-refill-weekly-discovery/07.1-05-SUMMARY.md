# Phase 07.1 Plan 05: GAP-02 — library_stats htmx polling-loop fix Summary

**One-liner:** Closed GAP-02 (NAS UAT 25-50 req/s infinite-loop polling against `/api/library/stats`) via a 1-line `hx-trigger` change in `app/templates/partials/library_stats.html` plus a 4-test regression-guard module that pins both the syntactic and behavioral invariant.

## What Was Built

### The 1-line fix (`app/templates/partials/library_stats.html` line 3)

```diff
- hx-trigger="load, every 10s"
+ hx-trigger="every 10s"
```

That is the entire production-code change. Everything else in the 24-line partial is preserved verbatim:

- `id="library-stats-card"` (HTMX swap target)
- `hx-get="/api/library/stats"` (route unchanged)
- `hx-target="#library-stats-card"` (self-target)
- `hx-swap="outerHTML"` (intentionally kept — the new partial carries the same id and triggers so subsequent polls hit the same route)
- All 18 lines of body content (labels + values rendered via Jinja vars)

### Why parent pages don't need to change

The partial is embedded in **three** pages, and each one carries its **own** one-shot `hx-trigger="load"` block that handles the initial render — independent of whatever trigger lives inside the partial itself:

- `app/templates/pages/settings.html:10` — `<div hx-get="/api/library/stats" hx-trigger="load" hx-target="this" hx-swap="innerHTML">`
- `app/templates/pages/debug_events.html:6` — same pattern
- `app/templates/pages/debug_vibes.html:9` — same pattern

After that initial server-side fetch the partial takes over its own polling via `every 10s` on its root `<div>`. Because the root div replaces itself via `outerHTML`, the next response has `hx-trigger="every 10s"` (NOT `load, every 10s`) — so the next swap only schedules the next 10-second tick rather than firing `load` immediately on the new element. No infinite loop, no flash of empty content on first page load.

### New regression-test module (`tests/test_library_stats_partial.py`)

134 lines, `TestLibraryStatsPartialPolling` class with 4 tests:

1. **`test_partial_contains_polling_only_trigger`** — primary syntactic guard. Asserts `hx-trigger="every 10s"` is in the response body, asserts neither `hx-trigger="load, every 10s"` nor `hx-trigger="load,every 10s"` (whitespace variant) is present, and runs a regex (`r'hx-trigger="load,\s*'`) catching any `load,` prefix.
2. **`test_partial_preserves_outerhtml_swap_target`** — defensive structural check. Asserts the four attributes that must NOT regress: `id="library-stats-card"`, `hx-target="#library-stats-card"`, `hx-swap="outerHTML"`, `hx-get="/api/library/stats"`.
3. **`test_partial_labels_still_render`** — mirrors `TestStatsEndpoint`'s label assertions so a single-file run on this module catches accidental body-content breakage (`Total tracks`, `Rated tracks`, `Last rating event`).
4. **`test_partial_response_is_idempotent_across_rapid_calls`** — strongest server-side proof available without browser automation. Three sequential calls to `/api/library/stats` complete in <5s and all three response bodies carry `hx-trigger="every 10s"` (and none carries `hx-trigger="load,`). Browser-side polling cadence verification is deferred to manual NAS UAT (HUMAN-UAT item #1).

Per the plan-checker correction (07.1-05-PLAN.md line 197-203), the module defines its own local `client(test_engine)` fixture by copying lines 14-27 verbatim from `tests/test_library_api.py`. `tests/conftest.py` does NOT expose a `client` fixture; promoting it would be an unrelated refactor and is explicitly out of scope for this plan.

2. Tail Composer logs / Tailscale proxy logs.

4. Confirm the "Library at a glance" card renders with values (`Total tracks`, `Rated tracks`, `Last rating event`) and updates every ~10 seconds when underlying data changes.
5. Close the tab. Confirm `/api/library/stats` requests stop entirely (polling is browser-side; no server cron involved).
6. Repeat with 2-3 tabs open: expect 6×N requests per minute (N = open tabs), still bounded.
