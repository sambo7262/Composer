# Phase 7.1 Plan 02: Weekly LLM Discovery Cron Summary

**One-liner:** Wired the once-weekly Sunday 03:00 UTC Anthropic discovery call (`discovery_call_weekly`) — D-A1 candidate filter, adaptive 3-7 pick count, hallucinated-ID guard, type-specific MaxTokensTruncationError retry (Blocker #5 bounded retry surface), and the W9-correct startup catch-up gate that fires inside `start_scheduler` only after the outer with-Session block closes.

## Accomplishments

- Closed the cost gap from Phase 7's $0.05/play LLM ranking to a $0.05/week LLM discovery (~$0.20/month steady state). Combined with Plan 01's zero-LLM SQL refill, monthly cost drops from $150 → $0.20.
- Bounded retry surface (Blocker #5): the discovery handler retries ONLY on `MaxTokensTruncationError` (typed exception added by Plan 01 STEP 4). Generic `ValidationError`, `RuntimeError`, and other failures propagate to the failure path on the first attempt — no broad except.
- Resilient startup catch-up (D-C2): if `DiscoveryState.last_discovery_run_at` is NULL or > 7 days ago, a 10-second-delayed `discovery_call_weekly` is scheduled on startup. Handles NAS-asleep-on-Sunday and first-deploy scenarios.
- W9 invariant respected: the catch-up gate is placed OUTSIDE the existing `with Session(engine) as session:` block in `start_scheduler`. `read_discovery_state` opens its own inner session via `_read_discovery_state_sync` (Phase 5 D-09 helper); the outer session always closes first.
- All Phase 5 D-09 sync-helper invariants preserved: every `Session(get_engine())` call in `suggestions_discovery.py` lives in a `_*_sync` function (`_read_discovery_eligible_sync`, `_read_cached_taste_profile_sync`, `_read_anthropic_credentials_sync`, `_write_discovery_picks_sync`, `_log_discovery_failure_sync`). The AST regression test `test_no_session_outside_sync_helper_in_suggestions_discovery` still passes.

## Key Invariants

1. **AnthropicClient is module-level** — tests monkeypatch `suggestions_discovery.AnthropicClient` to a `_FakeClient` stub. Production code uses `_read_anthropic_credentials_sync` to fetch (api_key, model) from the settings table; if that fails (no settings, raised in tests), placeholders are used since the constructor was already swapped.

2. **Bounded retry — Blocker #5** — the retry loop catches `except MaxTokensTruncationError` SPECIFICALLY. All other exception types (`ValidationError`, `RuntimeError`, network errors, etc.) hit the failure path on the first attempt. Verified by 3 dedicated tests:
   - `test_discovery_call_weekly_retries_once_on_max_tokens_truncation_error` (2 calls, second has 2× max_tokens)
   - `test_discovery_call_weekly_does_not_retry_on_generic_validation_error` (1 call only)
   - `test_discovery_call_weekly_does_not_retry_on_generic_runtime_error` (1 call only)
   - `test_discovery_call_weekly_does_not_retry_twice_on_repeated_truncation` (max 2 calls, no third)

3. **W9 nested-session avoidance** — the D-C2 catch-up gate sits OUTSIDE the existing `with Session(engine) as session:` block in `start_scheduler`. `read_discovery_state` opens its OWN inner session via `_read_discovery_state_sync`. Verified by `test_catch_up_gate_does_not_open_nested_session` (instrumented `Session.__exit__` + `read_discovery_state` event timestamps).

4. **Best-effort observability** — every failure path (no eligible candidates, no taste profile, breaker tripped, error, repeated truncation, unexpected exception) writes one `LLMUsage` row with `error_text` populated. The /debug/suggestions UI can read these for diagnosis without losing the cron run silently.

5. **Hallucinated-ID guard (Pitfall 10)** — picks with `track_id` NOT in the candidate pool are filtered AND a warning is logged. Tested in `test_discovery_call_weekly_filters_hallucinated_track_ids` (3 valid + 2 hallucinated → 3 written).

## Cron Registration Pattern

`schedule_discovery_call_weekly` mirrors `schedule_soft_negative_sweep` byte-for-byte:

```python
scheduler.add_job(
    discovery_call_weekly,
    trigger=CronTrigger(
        day_of_week="sun", hour=3, minute=0, timezone="UTC",
    ),
    id="discovery_call_weekly",
    replace_existing=True,
    name="Discovery call weekly (Sundays 03:00 UTC)",
)
```

The job is registered from `app/main.py::lifespan` AFTER `start_scheduler()` AFTER `schedule_soft_negative_sweep()` (same singleton scheduler).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Fixed impossible W9 test assertion**
- **Found during:** Task 3 GREEN
- **Issue:** The plan's `test_catch_up_gate_does_not_open_nested_session` asserted `max(session_exits) < min(reads)`. That's impossible because `read_discovery_state` invokes `_read_discovery_state_sync` via `asyncio.to_thread`, which opens its own inner Session whose `__exit__` fires AFTER the read returns. So `session_exits` always contains a timestamp newer than the first `read_discovery_state` event.
- **Fix:** Changed assertion to: "there must exist at least one `session_exit` BEFORE the first `read_discovery_state` event." This is the actual W9 invariant (catch-up gate runs outside the outer with-Session block) without conflating it with the helper's inner session bookkeeping.
- **Files modified:** `tests/test_sync_scheduler.py`
- **Verification:** Test now passes; deliberately moving the catch-up gate INSIDE the with-Session block (by hand-edit) makes the test fail with a clear W9-violation message — confirmed the assertion still catches the bug it's meant to catch.
- **Commit:** `8657c7a` (Task 3 GREEN)

**2. [Rule 3 — Blocking] `AnthropicClient()` no-arg constructor doesn't exist**
- **Found during:** Task 2 GREEN
- **Issue:** The plan's `<interfaces>` block and STEP 1 of Task 2 instantiated `AnthropicClient()` with no args, but the real class requires `(api_key, model)`. Calling no-arg would `TypeError` at production runtime.
- **Fix:** Added `_read_anthropic_credentials_sync` helper that reads `(api_key, model)` from the settings table via `settings_service.get_setting / get_decrypted_credential`. In tests where the settings table is empty, the helper raises and is caught — production code falls through with placeholder strings since the `AnthropicClient` symbol itself has already been monkeypatched to a `_FakeClient` stub that ignores its args.
- **Files modified:** `app/services/suggestions_discovery.py`
- **Verification:** All 13 `TestDiscoveryCallWeekly` tests pass; the constructor is exercised in every one via the `_FakeClient` stub.
- **Commit:** `eb9a9a1` (Task 2 GREEN)

**3. [Rule 3 — Blocking] `taste_profile_service.get_cached_taste_profile` doesn't exist**
- **Found during:** Task 2 GREEN
- **Issue:** The plan's `<interfaces>` block listed `get_cached_taste_profile()` on `taste_profile_service`. The real module has `get_current_profile()` (sync) — no async wrapper.
- **Fix:** Added `_read_cached_taste_profile_sync` in `suggestions_discovery.py` that selects `TasteProfile.id=1` directly inside a `_sync` helper (Phase 5 D-09 compliant); called via `asyncio.to_thread`. This avoids modifying `taste_profile_service.py` to add the missing function (out of scope).
- **Files modified:** `app/services/suggestions_discovery.py`
- **Verification:** Both skip-path tests (`_skips_when_no_taste_profile`, `_skips_when_no_eligible_candidates`) and all happy-path tests pass.
- **Commit:** `eb9a9a1` (Task 2 GREEN)

**4. [Rule 3 — Blocking] Catch-up coroutine resolves discovery handler lazily**
- **Found during:** Task 3 GREEN
- **Issue:** The plan's `start_scheduler` extension imported `discovery_call_weekly` at gate-evaluation time and bound the reference in the closure. Tests monkeypatch `suggestions_discovery.discovery_call_weekly` AFTER `start_scheduler` is called — the captured reference would point to the unpatched original.
- **Fix:** The `_delayed_catch_up_discovery` coroutine re-imports `from app.services import suggestions_discovery as _sd_inner` at await-time and calls `_sd_inner.discovery_call_weekly()`. This ensures test monkeypatches take effect.
- **Files modified:** `app/services/sync_scheduler.py`
- **Verification:** `test_schedules_catch_up_when_last_run_is_null` and `_is_stale` pass; the stubbed coroutine in those tests is actually invoked.
- **Commit:** `8657c7a` (Task 3 GREEN)
