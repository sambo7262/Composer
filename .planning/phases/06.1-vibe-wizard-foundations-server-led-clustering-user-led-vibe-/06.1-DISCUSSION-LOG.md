## Vibe-name-to-cluster algorithm

| Option | Description | Selected |
|--------|-------------|----------|
| k-means with k=N, LLM maps clusters→names | k-means runs first, LLM assigns best-matching user name to each cluster. Most accurate to actual taste. | |
| LLM imagines target centroids per name, distance-assign | LLM picks target features per name; tracks assigned by distance. Risks divorce from real library. | |
| Pure k-means + user names by position | Cheapest. No LLM in mapping. User name order = cluster order. | |
| Hybrid: LLM maps + flags poor fits | Same as #1 but adds `fit: strong/weak/no_match` grade per name with reason for no_match. | ✓ (recommended) |

**User's choice:** "what do you recommend here? the goal is to ensure that 'workout' tracks get to the 'workout' playlist -- the names will be simple and based on the 'vibe' (eg focus, dance, late night drive, synth heavy, etc)"
**Notes:** User asked for recommendation; Claude recommended #4 (Hybrid with fit grading). Rationale captured in CONTEXT.md D-NEW-01: real library clusters + LLM gets genre context for names like "synth heavy" + fit grading prevents another "10-track playlist" surprise. Trade-off: 1 LLM call per session, vs 1-10 in Phase 6's LLM-led flow.
