## Decisions Made

- **`mp.composer_name` not `mp.name`** (Rule 3 fix). The plan refers to `mp.name` throughout the migration step, but the actual `ManagedPlaylist` field is `composer_name` (verified via `app/models/vibe.py:112` and existing usages in `plex_playlist_service.py` lines 76/88/115 + `api_vibes.py:371`). All migration code and the regression test (`test_run_phase_61_migration_archives_legacy_playlists`) use `composer_name`. Documented as a deviation below.
- **D-NEW-09 wording amended: "(legacy)" → "(archived)"**. The existing `archive_playlist` helper renames to `"(archived)"` and deletes the `ManagedPlaylist` row in one shot. Adopting it directly avoids introducing a parallel `rename_playlist` + manual DELETE flow that would add surface area for no behavioral benefit (the user-visible string is cosmetic and both wordings communicate "this is the old wizard's playlist"). CONTEXT.md amended at execution time per the plan objective's "Note on archive wording".
- **Lazy import via attribute resolution**, not `from ... import name`. Inside `run_phase_61_migration()`, the archive call uses `from app.services import plex_playlist_service as _pps` then `await _pps.archive_playlist(...)`. The direct `from ... import archive_playlist` form would resolve the function at function-entry time, so `mock.patch("app.services.plex_playlist_service.archive_playlist", ...)` would NOT see the patched version. Attribute access on the module object lets the patch flow through.
- **Existing test rewriting, not deletion**. The previous `test_post_setup_propose_init_calls_initial_cluster_proposal` test was rewritten to test the new user-led path, not deleted. Phase 6.1 CONTEXT.md D-NEW-10 states the old `vibe_clustering_initial` path is removed from the wizard but `initial_cluster_proposal` the function still exists — `tests/test_vibe_clusterer.py` continues to exercise it directly. Plan-level intent: the WIZARD's initial-proposal slot is now user-led; the service-level function is still callable for future paths (e.g. "Suggest some for me" if deferred-idea bullet 3 is ever revisited).
- **Synchronous reslot (Blocker #7 Option A)**, NOT `asyncio.create_task` fire-and-forget. Tradeoff: ~30-90s in-flight POST on a 600-track library. Rationale: success criterion "≥30 tracks/vibe after finalize" must be UAT-observable when `/setup/done` renders. The wizard's sticky CTA already shows a loading state during the in-flight POST (Phase 6 D-09), so the user never sees a "pending slot-in" intermediate state. Verified by `test_finalize_synchronously_awaits_reslot_all_rated_tracks` (`reslot_mock.await_count == 1` by the time the response returns).
- **Existing finalize tests need reslot mocked**. Without the monkeypatch, the real `reslot_all_rated_tracks` iterates `_seed_rated_tracks(session, 60)` and calls `slot_track` for each, which hits Plex via `update_playlist_items` (Phase 6 D-09 path). 5 existing tests (2 in test_api_setup.py finalize, 3 in test_finalize_integration.py) were updated to add `monkeypatch.setattr(api_setup, "reslot_all_rated_tracks", AsyncMock(return_value=0))`. This is a test-side change only; the production reslot semantics are exercised by `test_finalize_synchronously_awaits_reslot_all_rated_tracks` and `test_reslot_all_rated_tracks_iterates_with_semaphore` (existing in test_vibe_service.py — still passes).
