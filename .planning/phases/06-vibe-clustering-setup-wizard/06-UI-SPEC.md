# Phase 6 — UI Design Contract

> Visual and interaction contract for the Vibe Clustering + Setup Wizard phase. Generated by gsd-ui-researcher 2026-05-09. Source-of-truth for the planner, executor, ui-checker, and ui-auditor on every Phase 6 surface.

**Phase scope (7 surfaces):**
1. `/setup` — Step 1: rating-source confirm (+ <30 cold-start gate, 30–49 degraded message)
2. `/setup/webhook` — Step 2: webhook config (conditional; reuses Phase 5 partials)
3. `/setup/propose` — Step 3: initial cluster proposal + conversational refinement loop *(flagship UX)*
4. `/setup/confirm` — Step 4: final review + Push to Plex
5. `/setup/done` — Step 5: success page
6. Settings page extensions — Re-cluster button + confirm modal + Run-wizard-again link + diagnostics footer link
7. `/debug/vibes` — operator diagnostics (DEBUG-02)

**Hard constraints (locked upstream — re-verified, not re-decided):**
- Stack: Tailwind 4 utility classes only · HTMX with `hx-ext="alpine-morph"` · Alpine.js for micro-interactions · Jinja2 extending `base.html` · NO new JS dependencies
- Mobile-first portrait at 375px wide is the primary target (user accesses via Tailscale from phone)
- Existing dark theme (CSS variables in `app/static/css/input.css`) is the only color system — no new palette
- The conversational refinement loop on `/setup/propose` is the user-stated "core of the app" — every other surface defers to it visually

## Spacing Scale

Declared values (multiples of 4 only, matching Tailwind 4 default scale):

| Token | px | Usage in Phase 6 |
|-------|----|------------------|
| xs | 4 | Inline icon gap (chip ↔ label), badge inner pad |
| sm | 8 | Card-internal control gap (name ↔ description), seed-track row gap |
| md | 16 | Default card padding, gap between proposal cards, inline form-field margin |
| lg | 24 | Section padding inside a card, gap between major page sections |
| xl | 32 | Page top padding above wizard step header (matches existing `pt-12` ÷ 1.5 — see exception) |
| 2xl | 48 | Wizard step transition margin, debug-page section breaks |
| 3xl | 64 | Footer bottom margin on `/setup/done` celebration page |

**Touch-target token (NEW — non-color, project-wide):**

| Token | Value | Source |
|-------|-------|--------|
| `--touch-target-min` | `44px` | Added to `app/static/css/input.css @theme` block per Pitfall 17 / UI-04. Applied via `min-h-11 min-w-11` Tailwind classes (11×4 = 44px) on every button, radio label, link-as-button, and tappable disclosure. |

### Exceptions

1. **`pt-12` (48px) container top padding from existing `base.html`** — kept as-is on every wizard step for visual consistency with v1 pages. Does not change in this phase.
2. **`safe-area-inset-bottom` padding on sticky-bottom bar (`/setup/propose` and `/setup/confirm`)** — variable Y-padding via `env(safe-area-inset-bottom)`; Tailwind escape: `pb-[env(safe-area-inset-bottom)]` added to a 16px base padding so total = 16 + iOS toolbar inset. Required by Pitfall 16.
3. **Adjacent destructive ↔ primary action buttons on the re-cluster confirm modal use 16px gap** (not 8px) per Pitfall 17 to prevent miss-taps.

## Typography

Exactly **4 sizes, 2 weights** (well within the 3–4 size, 2-weight max constraint):

| Role | px | Tailwind class | Weight | Line-height | Where |
|------|----|----|--------|------|-------|
| Body | 14 | `text-[14px]` | 400 (regular) | 1.5 (Tailwind default) | Refinement input, seed-track lines, disclosure copy, table rows |
| Label | 13 | `text-[13px]` | 400 (regular) | 1.4 | Helper text below the textarea, "Refinement N of 10" counter, member-count subtext, breadcrumbs, timestamps |
| Heading | 20 | `text-[20px]` | 600 (semibold) | 1.2 | Vibe-card title (proposal name in edit-mode it becomes an `input` styled the same), section headings (`/debug/vibes`) |
| Display | 28 | `text-[28px]` | 600 (semibold) | 1.2 | Page titles (`/setup`, `/setup/done`, `/debug/vibes`), step header on `/setup/propose` |

**Notes:**
- Sizes match what already ships in `settings.html` (`text-[22px]` for h1, `text-[20px]` for h2, `text-[15px]` body, `text-[13px]` secondary). Phase 6 normalizes the body down to 14px (denser mobile lists) and the page title up to 28px (more presence on the wizard's first impression). Existing pages are not retroactively changed.
- All weights are 400 or 600. No 500/700 introductions.
- Line-height defaults from Tailwind (1.5 body, 1.2 tight headings) are used as-is — no custom `leading-*` classes.
- Vibe-card editable name field at edit-mode uses the same `text-[20px] font-semibold` so the click-to-edit transition has zero visual jump.

## Color

60/30/10 split across the page surface area:

| Role | Token | Hex | Usage in Phase 6 |
|------|-------|-----|------------------|
| Dominant (60%) | `surface-primary` | `#1f1f23` | Page background, refinement-loop bg between cards |
| Secondary (30%) | `surface-card` + `surface-elevated` | `#2a2a2e` / `#35353a` | Vibe proposal cards, sticky-bottom bar, debug-page sections, modal panel, expanded disclosure |
| Accent (10%) | `accent` | `#e5a00d` (Plex amber) | See "Accent reserved for" below |
| Destructive | `error` | `#ef4444` | Reserved for: re-cluster confirm modal "Re-cluster" button border-l-4, LLM-call-failed error banner, circuit-breaker-hit message |

### Accent reserved for (explicit list — never used elsewhere):

1. **Primary CTA fill** — "Refine" button, "Looks good" button, "Push to Plex" button, "Re-cluster vibes" button (in settings, before confirm), "Refresh count" (cold-start), "Save selected URL" (webhook step — already amber from Phase 5)
2. **Active step indicator** — current step pill in the wizard breadcrumb (`Step 3 of 5`)
3. **Focused input border** — `border-border-focus` ring on the refinement textarea + name-edit input + force-k dropdown
4. **Vibe-card "edit mode" indicator** — 1px amber border on the name `input` field when the user is mid-edit
5. **Settings link "View vibes diagnostics →"** — accent-colored on hover (matches existing Phase 5 settings footer pattern)

**Accent NOT used for:** card backgrounds, body text, headings, secondary buttons, navigational links (except hover state on the diagnostics footer link), seed-track rows, audio-feature chips, member counts.

### Audio-feature chip color (per D-11)

The chip is text-only ("High energy · Fast tempo · Low danceability"), no background fill or pill. Color: `text-text-secondary` (gray). Punctuation separator: `·` (middle dot). No semantic color coding by feature — would balloon the palette and mislead (energy ≠ danger).

### State colors

| State | Token | Where |
|-------|-------|-------|
| Success | `success` `#22c55e` | Webhook-test-received chip (reused from Phase 5), Push-to-Plex completion banner |
| Error | `error` `#ef4444` | LLM-call-failed banner, circuit-breaker tripped, re-cluster commit partial-failure banner |
| Warning | `accent` `#e5a00d` | Re-purposed: "Refinement 9 of 10 — last turn before save-or-restart" hint (uses accent text, no separate warning color introduced) |

## Interaction Specs

### Wizard navigation (HTMX-driven multi-page)

- Each step posts to its own endpoint (`POST /api/setup/{step}/submit`) and receives an HTMX redirect (`HX-Redirect: /setup/<next>`) — full page navigation, refresh-safe, browser back/forward works.
- Refinement turns on Step 3 use HTMX in-page swap: form posts to `POST /api/setup/refine`, server returns the updated proposal-card list partial, swapped via `hx-target="#proposal-cards" hx-swap="morph:innerHTML"` (alpine-morph extension preserves Alpine state on each card).
- "Looks good" submission on Step 3 triggers a full-page navigation to `/setup/confirm` via `HX-Redirect`.

### Vibe-card edit-in-place (Alpine `x-data`)

- Name field: clicking the name (h3) reveals an `<input>` styled identically (text-[20px] font-semibold text-text-primary, transparent bg, accent border-bottom 1px). Blur or Enter commits to a hidden form field.
- Description field: same pattern but as `<input type="text">` styled at body size.
- Both edits commit to the SetupState's `draft_proposals_json` via the next "Refine" or "Looks good" submit — no auto-save per keystroke (avoids extra HTTP round-trips and keeps the LLM in charge of the canonical proposal between turns).

### Members disclosure (Alpine `x-collapse`)

- "Show all N tracks" button toggles `expanded` Alpine state.
- Expanded panel: bg-surface-elevated, max-h-64, overflow-y-auto, scrollable on mobile. Each member is a single-line `Title — Artist · {distance}` row at text-[13px].
- Members render as plain text (not links — the Plex linkout is Phase 7).

### Sticky-bottom CTA bar

- Always visible on `/setup/propose` and `/setup/confirm` regardless of scroll position.
- z-index: 30 (above content, below modal at z-40).
- Uses `position: fixed; bottom: 0` + `pb-[calc(16px+env(safe-area-inset-bottom))]` for iOS toolbar clearance.
- The button is full-width-minus-32px (16px gutters), `min-h-12` (48px) for ergonomic tap, `bg-accent hover:bg-accent-hover text-surface-primary font-semibold rounded-lg`.
- During an HTMX submission, the button shows "Pushing… {N}/{M}" disabled (60% opacity, no hover state).

### Re-cluster confirm modal (Alpine + HTMX hybrid)

- Trigger: clicking "Re-cluster vibes" on Settings sets `Alpine.$store.modal.recluster = true`.
- Modal: `position: fixed; inset: 0; bg-black/60` backdrop + `bg-surface-card rounded-lg p-6 max-w-md mx-auto mt-32` panel.
- Focus-trap: first focusable element (Cancel button) auto-focused via Alpine `x-init="$nextTick(() => $refs.cancel.focus())"`.
- Cancel: closes modal (Alpine `@click="open = false"`).
- Confirm: HTMX `hx-post="/api/vibes/recluster/start"` returns `HX-Redirect: /setup/propose`.
- Esc key closes modal: `@keydown.escape.window="open = false"`.
- Backdrop click closes modal: `@click.self="open = false"` on the backdrop.

### Refinement input — keyboard handling

- Cmd/Ctrl+Enter submits the form (Alpine `@keydown.meta.enter="submit()"` and `@keydown.ctrl.enter="submit()"`).
- Plain Enter inserts a newline (textarea default).
- Refine button is disabled when textarea is empty (Alpine `x-bind:disabled="!message.trim()"`).
- Refine button shows a spinner during HTMX request via HTMX `hx-indicator`.

### Cold-start "Refresh count" button

- HTMX-driven: `hx-get="/api/setup/rated-count"` swaps the count label.
- No page reload; the count display updates in place.

### Webhook test indicator (reused from Phase 5)

- HTMX poll every 2s as already implemented.
- No changes for Phase 6.
